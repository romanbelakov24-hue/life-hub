# life hub

Личный трекер расходов и учебный планер в одном интерфейсе. Данные лежат в базе
(Turso / libSQL), а не в браузере, — сайт открывается с телефона и с ноутбука с
одними и теми же записями.

**Стек:** Next.js 15 (App Router) · TypeScript · Turso (libSQL) · Tailwind CSS 4 ·
Recharts · lucide-react.

---

## Быстрый старт

```bash
npm install
```

```bash
npm run dev
```

Открыть <http://localhost:3000>. Dev-сервер **всегда** работает с локальным
файлом `local.db` в корне проекта — даже если рядом лежат ключи боевой базы.
Схема создаётся сама при первом обращении; первый зарегистрированный аккаунт
получает все строки без владельца (в том числе демо-данные).

Чтобы начать с чистого листа — удалить `local.db` и перезапустить.

## Демо-данные

```bash
npm run db:seed -- --yes
```

Траты за два месяца, дела, задачи, заметки, цели и показатели здоровья — только
в `local.db`. В боевую базу скрипт не пишет никогда.

## Тесты

```bash
npm test
```

Встроенный в Node раннер (`node:test` через tsx), без лишних зависимостей. Тесты
лежат рядом с кодом: `*.test.ts`. Самый важный — `src/lib/db/migrator.test.ts`:
он доказывает, что миграции создают ту же схему, что живёт на проде, и что
упавшая миграция откатывается целиком.

## База и миграции

Схема — нумерованный список миграций `MIGRATIONS` в `src/lib/db/schema.ts`.
Каждая выполняется ровно один раз, целиком в одной транзакции, и её номер
пишется в таблицу `schema_migrations`.

**Изменить схему** — добавить в конец списка новую миграцию со следующим номером.
Выпущенные миграции не правятся никогда. Миграция должна быть совместима с кодом,
который сейчас на проде (колонки добавляются с `DEFAULT`, удаляются отдельной
миграцией уже после деплоя кода без них).

| Команда | Что делает |
|---|---|
| `npm run db:migrate` | применить миграции к `local.db` (dev-сервер делает это сам) |
| `npm run db:status:prod` | показать, что не применено на боевой базе |
| `npm run db:migrate:prod` | применить миграции к боевой базе |

Ключи боевой базы для `--prod` лежат в `.env.prod.local` (в git не попадает):

```
TURSO_DATABASE_URL=libsql://life-hub-<аккаунт>.aws-ap-northeast-1.turso.io
TURSO_AUTH_TOKEN=<токен>
```

Этот файл не читают ни Next.js, ни сборка под Cloudflare. В `.env.local` ключей
боевой базы быть не должно: OpenNext зашивает `.env.local` в код воркера.

## Деплой на Cloudflare Workers

Сайт собирается OpenNext и живёт на <https://life-hub.aarara.workers.dev>.

Один раз — ключи базы в секреты воркера (значения из `.env.prod.local`):

```bash
npx wrangler secret put TURSO_DATABASE_URL
```

```bash
npx wrangler secret put TURSO_AUTH_TOKEN
```

Каждый деплой — сначала схема, потом код:

```bash
npm run db:migrate:prod
```

```bash
npm run cf:deploy
```

`cf:deploy` сначала запускает `scripts/check-deploy.ts` и останавливается, если
у воркера нет ключей базы или на боевой базе не применены миграции.

## Telegram-бот

Общий бот сайта — [@assistent_life_hub_bot](https://t.me/assistent_life_hub_bot).
Любой пользователь life hub подключает его в **Настройки → Telegram-бот**: кнопка
выдаёт одноразовую ссылку `t.me/…?start=<код>`, человек жмёт «Start», и бот
привязывает чат к аккаунту.

- Текст и голосовые разбирает **Cloudflare Workers AI** в том же аккаунте, где
  живёт сайт: Llama 3.3 70B для смысла, Whisper для голоса. Бесплатная квота —
  10 000 «нейронов» в сутки на весь сайт, на пользователя — 60 разборов в сутки
  (`AI_MESSAGES_PER_DAY`). Без ИИ бот понимает шаблоны (`src/lib/telegram/rules.ts`).
- Бот пишет задачи, дела, траты и заметки через `lib/mutations` — с той же
  проверкой, что у форм. Такие записи в интерфейсе помечены самолётиком.
- Под каждой записью в Telegram — «Отменить»; `/today` — сводка сейчас.
- **Сводка дня:** расписание воркера (`custom-worker.ts`, cron каждые 15 минут)
  вызывает `/api/cron/digest`; время и часовой пояс у каждого свои.

Подключение бота к сайту (один раз и при смене адреса сайта):

```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN
```

```bash
npm run cf:deploy
```

```bash
npm run telegram:setup
```

`telegram:setup` берёт `TELEGRAM_BOT_TOKEN` из `.env.prod.local`, регистрирует
вебхук с секретом, команды и описание бота. После этого бот больше не отдаёт
сообщения через `getUpdates`: программа, которая читала его так раньше, должна
перейти на другого бота.

Локальная проверка без Telegram: `TELEGRAM_API_BASE` подменяет api.telegram.org
фальшивым сервером (в проде игнорируется). ИИ в `next dev` выключен, пока не задано
`BOT_DEV_AI=1`: иначе dev-сервер тратит квоту Workers AI аккаунта, под которым
залогинен wrangler.

## Структура проекта

```
wrangler.jsonc               # воркер Cloudflare: имя, флаги совместимости
scripts/                     # миграции, демо-данные, проверки перед деплоем
src/
├── app/                     # маршруты (App Router)
│   ├── page.tsx             #   /          — обзор
│   ├── expenses/page.tsx    #   /expenses  — расходы (журнал + аналитика)
│   ├── schedule/page.tsx    #   /schedule  — расписание
│   ├── tasks/page.tsx       #   /tasks     — задачи
│   ├── notes/page.tsx       #   /notes     — заметки
│   ├── globals.css          #   дизайн-токены и базовые стили
│   ├── error.tsx            #   экран ошибки (чаще всего — нет связи с базой)
│   └── layout.tsx           #   шрифты, тема, каркас приложения
│
├── components/
│   ├── layout/              # сайдбар, нижний таб-бар, шапка, переключатель темы
│   ├── ui/                  # базовые примитивы: панель, кнопка, поля, модалка
│   ├── charts/              # общее для графиков: тема и тултип
│   ├── expenses/            # виджеты раздела расходов
│   ├── study/               # расписание, задачи, заметки
│   └── overview/            # карточки стартовой страницы
│
├── config/                  # то, что чаще всего хочется поменять
│   ├── nav.ts               #   пункты навигации
│   ├── schedule.ts          #   учебные дни, число пар, расписание звонков
│   ├── palette.ts           #   цвета категорий и предметов
│   └── icons.ts             #   иконки категорий
│
└── lib/
    ├── types.ts             # доменные типы — одна точка правды
    ├── db/                  # подключение к базе, миграции, чтение строк
    ├── queries/             # выборки из базы (только SQL, без логики)
    ├── actions/             # серверные действия: создание, правка, удаление
    ├── analytics/           # чистые функции: агрегация трат, матрица задач
    └── utils/               # даты, форматирование, разбор быстрого ввода
```

### Как это устроено

**Слои данных.** `queries/` только читает из базы, `analytics/` только считает
над уже загруженными массивами, `actions/` только пишет. Страницы остаются
тонкими: получили данные — отдали в компоненты. Если нужно поменять формулу
среднего чека, правится один файл в `analytics/`, SQL трогать не приходится.

**Серверные действия вместо API-роутов.** Все изменения идут через функции с
`"use server"` в `lib/actions/`. Они валидируют вход, пишут в базу и вызывают
`revalidatePath`, после чего серверные страницы перечитывают данные сами —
отдельного слоя fetch на клиенте нет.

**Ошибки не бросаются наружу.** Действие всегда возвращает
`{ ok: true, data }` либо `{ ok: false, error }`, и компонент показывает текст
ошибки рядом с формой (см. `lib/actions/types.ts`).

**Состояние страницы в URL, состояние виджета — в компоненте.** Месяц и вид на
странице расходов лежат в `?month=&view=` (ссылку можно сохранить, кнопка
«назад» работает), а переключатель «список ↔ матрица» на задачах — обычный
`useState`, потому что это взгляд на те же данные, а не отдельная страница.

## Как вносить изменения

| Что нужно | Куда смотреть |
|---|---|
| Добавить раздел в меню | `src/config/nav.ts` + новая папка в `src/app/` |
| Изменить цвета или тему | блоки `:root` и `.dark` в `src/app/globals.css` |
| Другое расписание звонков, шестидневка | `src/config/schedule.ts` |
| Новые иконки категорий | `src/config/icons.ts` |
| Подсказки для быстрого ввода трат | `KEYWORD_HINTS` в `src/lib/utils/quick-parse.ts` |
| Новое поле в таблице | новая миграция в конце `MIGRATIONS` (`src/lib/db/schema.ts`), затем типы в `src/lib/types.ts`, запрос и действие |
| Новая метрика в статистике | `src/lib/analytics/expenses.ts` |

Подробнее о схеме — раздел «База и миграции» выше.

## Дизайн

Оформление собрано вокруг «бумажной» метафоры: тёплый фон, разделители
волосяными линиями вместо теней, крупные моноширинные цифры и один акцентный
цвет — вермилион. Заголовки набраны Unbounded, интерфейсный текст — Inter,
все числа — JetBrains Mono (моноширинные, поэтому колонки сумм не «прыгают»).

Тема переключается вручную (светлая / тёмная) или следует настройке устройства.
Цветовые пары проверены на контраст не ниже 4.5:1, цели касания — от 44px,
нижняя навигация учитывает безопасную зону экрана телефона.
